# Windows 兼容与验收

## 责任与范围

Windows 兼容问题由 Windows 电脑上的负责人处理并实机验收。Mac 侧的跨平台代码与安装包内容检查不代表 Windows 运行通过。

目标平台为 Windows 10 / 11 x64。当前版本的 Windows 安装包构建与实机兼容结论由 Windows 端提供。macOS 当前交付 Apple Silicon、macOS 13 及以上；手机端不在当前开发和发行范围。

正式数字签名暂缓，保留未签名构建。Windows 安装提示应纳入实机记录。

## 接入

使用 Node.js 24.22.0 或更新的 24.x；仓库存在 `.node-version` 时以该文件为准。验收前记录 `git rev-parse HEAD` 与 `package.json` 的版本，保留现有资料目录，使用独立用户资料进行全新安装验证。

```sh
npm ci --cache ./tmp/npm-cache
npm test
npm run build
npm run package:win
```

安装包不要求终端用户安装 Node.js、Docker 或配置 NAS。

文档与通用功能代码分开交接。先验收 GitHub 当前版本已有的安装、本机保存、代理和媒体能力。启动恢复、升级前备份、受控登录弹窗、许可打包、版本统一与部署配置由 Mac 端维护；对应代码到位后再补验。尚未出现在所验代码中的功能记录为“待代码同步”，不重复实现，也不据此认定为 Windows 独有故障。仓库提供 `release:check` 脚本后，同时运行 `npm run release:check`。

## 必验流程

| 项目 | 验收内容 | 当前状态 |
|---|---|---|
| 安装 | 普通用户、中文用户名、带空格的安装目录；安装、启动、卸载 | 待实机验收 |
| 本机资料库 | 不配置远程服务即可导入、搜索、整理、保存视频和重启保留 | 待实机验收 |
| X 登录 | 用户名或邮箱密码、二次验证、登录保留、退出；Apple 跳转；Google 返回 X 登录 | 待实机验收 |
| 网络 | 直接联网、系统代理、常用代理模式；本机回环连接不被误代理 | 待实机验收 |
| 同步 | 收藏、点赞、新增去重、停止、失效登录与限流提示 | 待实机验收 |
| 媒体 | 图片、视频声音、拖动进度、下载保存；浏览不自动缓存 | 待实机验收 |
| 远程资料库 | 配对、本机与远程切换、离线回退、加密凭证及重启保留 | 待实机验收 |
| 显示与输入 | 100% / 125% / 150% 缩放、常见分辨率、中文输入、浅深色 | 待实机验收 |
| 升级与恢复 | 覆盖安装保留资料；备份、迁移回滚、启动失败提示和恢复菜单 | 待实机验收 |
| 发行内容 | 程序与当前构建一致、版本号正确、附带协议与第三方许可 | 待实机验收 |

系统加密凭证属于当前电脑和用户，不能把 Mac 的 `connection.enc` 或 X 会话文件直接复制到 Windows 使用。迁移正文与整理信息使用 JSON 导出导入；已保存媒体使用完整资料库目录备份。Windows 首次连接远程资料库需单独配对。

## 结果要求

验收结果写入本文和 [验证与平台状态](验收记录.md)：代码版本、系统版本、处理器、安装包 SHA-256、各项实际结果、未解决问题及复现步骤。未运行的项目保留“待验”，不要仅凭构建成功标记通过。

测试资料、日志和截图存放在项目 `tmp`；交付证据可放在被 Git 忽略的 `release`。公开资料中不包含账号、Cookie、设备凭证、个人路径或内网地址。经用户验收并明确授权后才提交推送。

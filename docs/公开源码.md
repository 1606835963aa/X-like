# 公开源码交付

个人开发仓库与公开源码分开保存。公开交付使用不含 Git 历史的源码包；个人开发仓库保持私人，原提交和已发布安装包保留。

## 生成与验收

```sh
npm test
npm run test:collector
npm run build
npm audit --audit-level=moderate
npm run release:check
npm run release:source
```

输出为 `release/Shizang-<版本>-source.tar.gz`。包中包含源码、构建配置、锁文件、许可、双语 README、问题表单、安全政策、贡献指南及用户文档；`SOURCE_MANIFEST.json` 列出源文件。

源码包从当前工作文件生成，因此包含未提交的代码和文档。Git 历史、账号、个人配置、资料库、安装包、依赖目录和临时文件不进入源码包。

在项目 `tmp` 中解压后，可使用独立依赖验证：

```sh
npm ci --cache ./tmp/npm-cache
npm test
npm run build
npm run release:check -- --history
```

无独立 Git 仓库的源码目录不包含提交历史。检查不会借用上级私人仓库的历史；已有独立 Git 仓库时检查其可达提交。原私人仓库的历史检查仍会指出旧部署信息。

Mac 安装包需核对本地签名、中文文件名、执行权限、符号链接和文件完整性。Windows 安装包需核对程序内容、架构、版本与许可，实机范围见 [Windows 验收](Windows验收.md)。安装包与源码版本一致，文件校验值随安装包保存。

## 公开操作

公开操作在用户验收并明确授权之后进行：

1. 以验收后的源码包创建独立公开仓库，不复制原仓库的 `.git`。
2. 根据实际公开仓库地址核对 README、软件帮助菜单、反馈表单和文档链接。
3. 为同一份代码建立版本标签，发布对应的桌面包和校验值，提供对应源码。
4. 开启 GitHub Private vulnerability reporting，验证私密安全报告、功能错误与建议入口。GitHub 的配置方法见 [官方说明](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)。
5. 检查新仓库的源码、分支、标签、附件与 Actions 日志，确认公开范围。

公开仓库作为后续协作入口，私人开发历史单独留存。原私人仓库可见性不随源码导出而改变。

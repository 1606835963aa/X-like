# 公开源码交付

公开交付包含经过检查的源代码、分支与版本标签，以及同版本的桌面安装包、源码包和校验文件。仓库在验收并明确授权公开之前保持私人。

## 生成与验收

```sh
npm test
npm run test:collector
npm run build
npm audit --audit-level=moderate
npm run release:check -- --history
npm run package:mac
npm run package:win
npm run release:source
npm run release:checksums
```

输出为 `release/Shizang-<版本>-source.tar.gz`。包中包含源码、构建配置、锁文件、许可、双语 README、问题表单、安全政策、贡献指南及用户文档；`SOURCE_MANIFEST.json` 列出源文件。

源码包从当前工作文件生成，因此包含未提交的代码和文档。Git 历史、账号、个人配置、资料库、安装包、依赖目录和临时文件不进入源码包。

在项目 `tmp` 中解压后，可使用独立依赖验证：

```sh
npm ci --cache ./tmp/npm-cache
npm test
npm run build
npm run release:check -- --history
```

无独立 Git 仓库的源码目录不包含提交历史。检查不会借用上级仓库的历史；已有独立 Git 仓库时检查其可达提交。待公开的分支与标签均须通过历史检查。历史备份保存在 Git 忽略的 `private` 目录，不作为公开附件。

当前文件与待推送的新提交均检查测试文件中的内网地址，包括拆成数组再拼接的常见写法；演示地址统一为 `192.168.1.100`。历史测试样例中的内网地址可以保留，凭证和私人文件仍须清除。安装依赖后启用本地推送检查，GitHub Actions 对新增提交执行同样检查。

清理远端历史时，保留原仓库备份和提交映射，核对远端分支及标签没有其他新提交后再替换。其他电脑上的协作副本需要重新克隆。GitHub 缓存、历史 PR 引用与其他副本不由本地历史重写自动清除；有关范围见 [GitHub 说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

Mac 安装包需核对本地签名、中文文件名、执行权限、符号链接和文件完整性。Windows 安装包需核对程序内容、架构、版本与许可，实机范围见 [Windows 验收](Windows验收.md)。安装包与源码版本一致，文件校验值随安装包保存。

## 公开操作

公开操作在用户验收并明确授权之后进行：

1. 核对已验收提交、待发布分支和标签；确认历史检查通过，私人备份及配置不进入公开范围。
2. 根据实际公开仓库地址核对 README、软件帮助菜单、反馈表单和文档链接。
3. 为同一份代码建立版本标签，发布对应的桌面包和校验值，提供对应源码。
4. 开启 GitHub Private vulnerability reporting，验证私密安全报告、功能错误与建议入口。GitHub 的配置方法见 [官方说明](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)。
5. 检查仓库的源码、分支、标签、附件与 Actions 日志，确认公开范围。

源码导出、安装包构建和历史清理均不改变仓库可见性。

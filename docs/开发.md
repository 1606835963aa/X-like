# 开发与构建

当前交付范围是 macOS Apple Silicon 和 Windows x64。Windows 兼容性由 Windows 电脑上的负责人处理，任务和验收要求见 [Windows 兼容与验收](Windows验收.md)。安卓与 iOS 工程保留，当前不开发、打包或发布手机端。

## 环境与运行

需要 Git、Node.js 24.22.0 或更新的 24.x。固定构建版本见 `.node-version`，最低要求在 `package.json` 的 `engines` 中声明。

```sh
npm ci --cache ./tmp/npm-cache
npm run build
npm start
```

`npm run dev` 启动网页开发服务；桌面入口是 `dist/desktop/main.cjs`。默认资料库位于系统“拾藏”应用数据目录中的 `library`，无需额外服务。

从源码首次启动桌面、运行采集场景或打包时，Electron 会下载当前系统的运行时。普通桌面安装包已内置运行时。只构建网页与资料库服务时不需要下载它。

## 目录

| 目录 | 内容 |
|---|---|
| `src/ui` | React 界面与主题 |
| `src/desktop` | Electron 桌面、登录与同步 |
| `src/server` | SQLite 资料库、共享服务与恢复 |
| `src/shared` | 资料类型、解析、目录匹配、版本与诊断 |
| `scripts` | 环境检查、构建、部署配置和发行检查 |
| `tests` | 单元、接口与模拟采集检查 |
| `public` / `resources` / `design` | 图标、桌面资源与设计规范 |
| `android` / `ios` | 当前未交付的手机原生工程 |
| `private` / `data` | 本机配置、签名和资料，Git 忽略 |
| `dist` / `release` / `tmp` | 构建内容、发行包与临时文件，Git 忽略 |

## 检查

```sh
npm test
npm run test:collector
npm run build
npm run release:check
npm audit --audit-level=moderate
```

GitHub Actions 在 Mac、Windows 和 Linux 执行环境检查、测试与生产构建，Linux 另运行模拟采集场景。Linux 检查用于资料库服务，不提供 Linux 桌面安装包。云端检查通过状态由实际工作流结果确认，不代替 Windows 真机验收。

## 桌面发行

```sh
npm run package:mac
npm run package:win
npm run release:source
npm run release:checksums
```

Mac 输出 `release/mac-arm64/拾藏.app` 和 `release/Shizang-<版本>-macOS-arm64.zip`；Windows 输出 `release/Shizang-<版本>-Windows-x64.exe`。

源码包为 `release/Shizang-<版本>-source.tar.gz`。三个文件都生成后，`release:checksums` 按 `package.json` 中的版本生成同一份 `SHA256SUMS-<版本>.txt`；缺少任一同版本文件时停止，不生成不完整的校验文件。

版本号以 `package.json` 为准，界面、服务健康接口和安装包使用同一版本。修改版本时更新 `package-lock.json`，`release:check` 会检查一致性。数据库结构版本与应用版本独立。

正式签名暂缓：Mac 使用临时签名，Windows 不使用发布者数字签名。发行包随附 AGPLv3 与 `legal/THIRD_PARTY_NOTICES.txt`，Electron、Chromium 许可随桌面运行时分发。

## 启动与恢复

启动失败会显示错误说明，可打开资料目录、日志目录、重试或选择备份恢复。正常运行时，应用菜单“资料库”提供目录入口及“重启并恢复本机资料库”。有同步或视频保存任务时，需要先结束任务。

数据库结构升级前，程序在 `library/backups` 生成经校验的 SQLite 备份。备份失败则停止升级；升级失败回滚事务。高于当前结构版本的数据库不会被旧软件打开或降级。恢复会另外保留当前数据库及 WAL 文件，不改动媒体目录。

共享服务的命令行恢复见 [共享资料库](共享资料库.md)。启动日志位于应用数据目录 `logs/startup.log`；共享服务日志位于资料目录 `logs/startup.log`。连接日志位于应用数据目录 `connection.log`，保留操作阶段、连接方式、状态码与错误码，隐藏代理地址、服务地址和凭证。现有连接日志在首次写入时一起脱敏，单份日志约 1 MiB 后轮转，单条记录最多保留 20000 个字符。

用户安装和更新见 [安装与更新](安装与更新.md)，反馈方式见 [反馈与诊断](反馈与诊断.md)。依赖锁文件通过 `xcode → uuid` 覆盖规则固定 `uuid@11.1.1`，兼容性测试覆盖 CommonJS 项目解析、标识生成与写入后重新解析。

构建依赖使用定向覆盖固定 ASAR、universal、filelist、minimatch、glob 与 rimraf 的兼容补丁版本。`npm ci` 的安装后脚本为 `temp@0.9.4` 保留回调与同步清理接口，底层使用新版 rimraf；脚本可重复执行，依赖版本或原文件不匹配时停止。兼容检查覆盖中文归档路径、二进制解包、文件匹配和临时目录清理。

## X 登录与网络

X 用户名、邮箱或手机号与密码在官方 X 页面填写；登录状态保存在当前电脑。登录窗口允许 X 与 Apple 登录域名和受控弹窗，拦截其他页面。Google 不支持此类内嵌浏览器，程序会提供返回 X 登录的入口。没有 X 密码的 SSO 账号可按 [X 官方说明](https://help.x.com/en/managing-your-account/sso) 设置密码。

X 连接使用系统代理。只在浏览器扩展内生效的代理不会自动用于桌面程序。账号登录与网络环境验收见 Windows 文档；Apple 真实账号的完整登录仍需要对应账号验证。

## 共享服务与 NAS

```sh
npm run build
npm run server
```

`setup:shared` 为 Docker 生成 `.env`，保留已有设置，并根据资料目录拥有者填写运行用户和组。非 Docker 服务可通过 `SHIZANG_DATA_DIR`、`SHIZANG_NAME`、`HOST`、`PORT` 配置；Docker 配置见 [NAS 部署](NAS部署.md)。

生成 ARM64 离线服务包需要 `crane`、`tar` 和 `zip`：

```sh
node scripts/package-nas.mjs
```

`CRANE_BIN` 可指定工具路径。包名和镜像版本来自 `package.json`，包内包含部署配置示例、恢复命令、项目协议及第三方许可。

## 公开源码准备

```sh
npm run release:check
npm run release:source
npm run release:check -- --history
```

源码包位于 `release/Shizang-<版本>-source.tar.gz`，包含源文件清单和许可，不包含 `.git`、个人配置、数据库、签名或安装包。它从当前工作文件生成，未提交内容也会包含在内，发行前应确认工作区内容。

公开前检查待发布分支和标签的完整历史。发现个人部署信息时，先保留 Git 忽略的私人备份，再清理历史，并核对所有版本标签。历史清理涉及远端替换时，需要使用保留远端版本校验的推送方式；其他协作副本应重新克隆，避免重新带入旧提交。未经验收与明确授权，仓库保持私人。

源码包支持在没有 Git 历史的目录独立运行发行检查，目录位于另一仓库内部时也只扫描当前源码。交付包包含安全政策、贡献指南、问题表单和安装、诊断文档。验收与公开方法见 [公开源码交付](公开源码.md)。

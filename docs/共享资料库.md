# 共享资料库

共享资料库可以运行在普通电脑、云服务器、家庭服务器或 NAS 上。只在一台电脑使用拾藏时，直接使用默认的本机资料库即可，无需启动这项服务。

## 在普通电脑上运行

需要 Node.js 24.22.0 或更新的 24.x。在项目目录完成构建并启动服务：

```sh
npm ci --cache ./tmp/npm-cache
npm run build
npm run server
```

默认端口为 `5368`，启动时终端会显示连接码。

- 同一台电脑上的拾藏：在设置中连接 `http://127.0.0.1:5368`。
- 另一台电脑：填写服务电脑的局域网地址，例如 `http://192.168.1.100:5368`。
- 两台设备填写同一个连接码；已连接的电脑也可以在设置中显示连接码。

运行服务的电脑需要保持开机。设备要处于可互通的网络中，服务电脑需要允许设备访问 `5368` 端口。跨网络使用私网连接，或为服务配置 HTTPS 反向代理。

## 本机资料与共享资料

桌面默认的本机资料保存在系统“拾藏”应用数据目录中。独立服务的资料默认保存在项目 `data` 目录，两者是不同的资料库。

电脑版连接远程资料库后，可在“设置 → 资料库”直接切换本机和远程。地址与连接凭证加密保留，切换及重启不需要重新输入连接信息。需要使用其他远程地址时，选择“更换远程资料库”。

切换不会自动搬移资料或启动 X 同步。远程服务暂时离线时，可以切回本机继续使用；本机模式启动不连接远程服务。

将本机已有内容放入共享资料库时：

1. 在本机资料库的设置中导出 JSON。
2. 切换到共享资料库。
3. 导入刚才导出的备份。

其他电脑之后连接这一份共享资料库，由登录 X 的电脑同步新增内容。切换资料库不会自动搬移已有资料。当前仅交付 Mac 和 Windows。

## 配置

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| `SHIZANG_DATA_DIR` | `data` | 持久资料目录 |
| `SHIZANG_NAME` | `拾藏 · 共享资料库` | 设备上显示的名称 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `PORT` | `5368` | 服务端口 |

Docker 和 NAS 的部署方法见 [NAS 部署](NAS部署.md)。

## 备份

停止服务后复制完整 `data` 目录，再重新启动服务。该目录保存正文、整理信息、媒体文件与设备连接配置。JSON 导出适合迁移正文与整理信息；手动保存的视频通过完整目录备份保留。

数据库结构升级前自动生成 `data/backups/library-before-v<结构版本>-<时间>.sqlite`。备份通过校验后才执行升级；升级失败会回滚。它只备份数据库，完整资料备份仍需复制整个资料目录。

停止对应资料库后，可列出和恢复升级前备份：

```sh
npm run restore:library -- --data-dir ./data --list
npm run restore:library -- --data-dir ./data --backup <备份文件路径>
```

路径含空格时使用引号。恢复前的数据库及 WAL 文件保存在 `data/backups/before-restore-*`，媒体目录不变。Mac 和 Windows 本机资料也可通过应用菜单“资料库 → 重启并恢复本机资料库”选择备份。

独立服务无法启动时会在终端说明原因，并将诊断写入 `data/logs/startup.log`。端口冲突可调整 `PORT`，权限问题应调整资料目录或运行用户。Docker 的 `.env` 仅用于 Compose；普通 Node 服务使用上表的进程环境变量。
